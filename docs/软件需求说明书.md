## 2. 总体描述

### 2.1 产品视角

系统采用 B/S 架构，部署于 Linux 课程服务器：

```
浏览器 ← HTTP/JSON → server (C11 + libmicrohttpd) ← SQLite3
                          ↕ libcurl (API 代理)
                      大模型 (OpenAI 协议)
```

### 2.2 用户特征

| 角色 | 人数 | 技术水平 | 主要场景 |
|------|------|----------|----------|
| 管理员 | 1 | 技术 | 用户管理、系统配置、审计 |
| 教师 | 多 | 非技术 | 题库管理、试卷管理、AI 配置 |
| 学生 | 多 | 非技术 | 浏览题目、AI 答疑、讨论追问 |

### 2.3 运行环境

| 环境 | 要求 |
|------|------|
| 操作系统 | Ubuntu/Debian Linux |
| 编译器 | gcc（支持 C11） |
| 系统依赖 | libmicrohttpd、libcurl、libsqlite3、libcrypto |
| 浏览器 | Chrome/Firefox/Edge 最新版 |
| 端口 | 8000（默认，可配置） |

## 3. 功能需求

### 3.1 用户认证模块

#### F-01 登录

| 属性 | 值 |
|------|-----|
| 优先级 | P0 - 必须 |
| 接口 | `POST /api/v1/auth/login` |
| 输入 | `{"username":"...", "password":"..."}` |
| 输出 | `{"token":"...", "user":{"id", "username", "name", "role"}}` |
| 错误 | 400/401/500 |

**详细规则**：
- 密码使用 SHA-256(salt || password) 哈希比对
- 用户名不存在与密码错误均返回 401，防枚举攻击
- 成功登录后创建 64 位十六进制 Token，有效期 24 小时
- 预设 Demo 账号：admin(admin123)、teacher(teacher123)、student(student123)

#### F-02 登出

| 属性 | 值 |
|------|-----|
| 优先级 | P0 - 必须 |
| 接口 | `POST /api/v1/auth/logout` |
| 鉴权 | Bearer Token |
| 输出 | `{"status":"ok"}` |

#### F-03 当前用户信息

| 属性 | 值 |
|------|-----|
| 优先级 | P0 - 必须 |
| 接口 | `GET /api/v1/auth/me` |
| 鉴权 | Bearer Token |
| 输出 | `{"user":{"id","name","role"}}` |
| 错误 | 401（token 无效/过期） |

### 3.2 题库管理模块

#### F-04 题目 CRUD

| 属性 | 值 |
|------|-----|
| 优先级 | P0 - 必须 |
| 接口 | `GET/POST/PUT/DELETE /api/v1/questions/*` |
| 鉴权 | Bearer Token（教师/管理员可写，学生仅可读） |

**题目字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | INTEGER | 自动 | 主键 |
| title | TEXT | 是 | 题目标题 |
| content | TEXT | 是 | 题干内容 |
| type | TEXT | 是 | 题型（单选/多选/填空/简答/编程） |
| options | JSON | 否 | 选项列表 |
| answer | TEXT | 否 | 标准答案 |
| analysis | TEXT | 否 | 解析 |
| difficulty | INTEGER | 否 | 难度 1–5 |
| tags | JSON | 否 | 知识点标签 |
| teacher_id | INTEGER | 自动 | 所属教师（多租户隔离） |
| status | TEXT | 自动 | active/archived |
| created_at | TEXT | 自动 | 创建时间 |
| updated_at | TEXT | 自动 | 更新时间 |

#### F-05 题目批量导入

| 属性 | 值 |
|------|-----|
| 优先级 | P1 |
| 支持格式 | Word、PDF、Markdown、LaTeX、图片、纯文本 |
| 说明 | 系统自动解析并拆分多道题目 |

#### F-06 题目搜索与筛选

| 属性 | 值 |
|------|-----|
| 优先级 | P1 |
| 筛选项 | 题型、难度、标签、关键词、状态 |

### 3.4 AI 智能解答模块

#### F-09 AI 解答生成

| 属性 | 值 |
|------|-----|
| 优先级 | P0 - 必须 |
| 接口 | `POST /api/v1/ai/answer` |
| 鉴权 | Bearer Token |
| 说明 | 后端代理调用大模型，构建 Prompt 上下文（题干+选项+答案），API Key 不出后端 |

**AI 解答流程**：
1. 题目进入题库
2. 教师开启 AI 解答并配置参数（模型、temperature、max_tokens、Prompt 模板）
3. 系统构建上下文
4. 调用大模型获取解答
5. 返回结构化解答

#### F-10 AI 配置管理

| 属性 | 值 |
|------|-----|
| 优先级 | P0 |
| 配置项 | 模型选择、temperature、max_tokens、Prompt 模板 |

**支持的环境变量**：

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `AI_API_BASE_URL` | API 地址 | `https://api.openai.com/v1` |
| `AI_API_KEY` | API Key | 空（必填） |
| `AI_MODEL` | 模型名称 | `gpt-4o-mini` |

### 3.5 分支对话树模块

#### F-11 对话树创建与管理

| 属性 | 值 |
|------|-----|
| 优先级 | P0 - 必须 |
| 接口 | `GET/POST /api/v1/conversations/*` |
| 鉴权 | Bearer Token |

**功能**：
- 对任意题目创建对话节点
- 从任意节点 Fork 分支讨论
- 多路径讨论树展示
- 节点折叠/展开
- 搜索定位
- 推荐答案标记

**对话树数据结构**：

```
ConversationNode {
  id: INTEGER
  question_id: INTEGER
  parent_id: INTEGER (NULL = 根节点)
  user_id: INTEGER
  content: TEXT
  role: "user" | "assistant"
  created_at: TEXT
}
```

## 4. 外部接口

### 4.1 用户接口

- 前端为纯 HTML/CSS/JS，由 C 服务端直接托管
- 浏览器访问 `http://<IP>:8000`

### 4.2 硬件接口

无特殊硬件要求。

### 4.3 软件接口

| 接口 | 说明 |
|------|------|
| libmicrohttpd | HTTP 服务框架 |
| SQLite3 | 数据持久化 |
| libcurl | AI API 代理调用 |
| cJSON | JSON 解析/生成 |
| OpenSSL libcrypto | SHA-256 密码哈希 |

### 4.4 通信接口

- HTTP/1.1，Content-Type: application/json
- 鉴权：Bearer Token (Authorization header)
- 所有 API 路径前缀：`/api/v1/`

## 5. 非功能需求

### 5.1 性能

| 指标 | 要求 |
|------|------|
| API 响应时间 | < 200ms（不含 AI 调用） |
| AI 调用 | 异步处理，超时 30s |
| 并发 Session | 最多 128（Demo 阶段） |

### 5.2 安全性

| 要求 | 说明 |
|------|------|
| 密码存储 | SHA-256(salt + password) |
| 传输安全 | HTTPS（生产环境） |
| API Key 保护 | 仅后端持有，不暴露前端 |
| 路径穿越防护 | 拒绝含 `..` 的静态文件路径 |
| SQL 注入防护 | 参数化查询 |
| 多租户隔离 | 所有查询带当前用户/教师上下文 |
| 登录防枚举 | 统一返回 401 |

### 5.3 可用性

- 系统高可用（Demo 阶段单实例可接受）
- 服务异常时优雅降级

### 5.4 可维护性

- 模块化架构（路由/业务/数据/AI 四层分离）
- monorepo 扩展支持（一个模块一个目录，自带 Makefile）
- 详细日志记录
