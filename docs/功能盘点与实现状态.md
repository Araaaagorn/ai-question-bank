## 一、项目总体架构

### 1.1 技术栈与部署形态

| 层 | 技术 | 职责 |
| --- | --- | --- |
| web（前端） | 纯 HTML/CSS/JS，无构建工具链 | hash SPA，9 个页面，由 C 后端直接托管；支持 file:// 离线演示降级 |
| server（后端） | C11 + libmicrohttpd + SQLite3 + libcurl + cJSON + OpenSSL | 唯一公共业务入口：认证、题目、试卷、导出、AI 任务代理、教师 API 配置 |
| ai-service（AI） | Node.js ≥22.19 + TypeScript + Pi 0.84.1 | 内部模型执行、教学技能、异步任务队列；仅监听 127.0.0.1:8001 |
| 存储 | SQLite（经 kv_store 目录式 KV + 少量关系表） | users/qdata/edata 走 KV；AI 授权/教师 API/额度走关系表 |

### 1.2 服务调用关系与核心数据流

```
浏览器 ──HTTP/JSON──▶ C 后端(libmicrohttpd, :8000) ──SQLite──▶ 数据
                        │  (libcurl, 内部 HTTP, AI_SERVICE_TOKEN)
                        ▼
                    Pi AI 服务(:8001) ──▶ DeepSeek 兼容模型(或 Mock)
```

关键链路：

1. **认证链路**：登录/注册 → `routes.c` → `auth.c`（内存 session）→ `db.c`（经 `kv_store` 读写 `users`）。
2. **题目/试卷链路**：前端 fetch → `route_dispatch` → `handle_questions`/`handle_exams` → `kv_store`（`qdata`/`edata`）或 `exams.c`/`export.c`。
3. **AI 链路**：前端 `POST /api/v1/chat` → C 校验登录/权限/题目/额度 → 组装内部请求（含题目、message、execution 加密密钥）→ `ai_client.c` 调 Pi `POST /internal/v1/jobs`（202）→ Pi `jobs.ts` 入队 → `agent.ts` 执行模型/工具 → 前端轮询 `GET /chat/{job_id}` 获取结果。

C 对内部 Pi 请求只等待最多 2 秒（提交/查询/取消），模型执行在 Pi 后台队列，不占用 C 的 MHD 轮询线程。

### 1.3 AI 路由模式

默认 `AI_ROUTING_MODE=teacher`（教师自管 API）；显式 `platform` 为旧平台统一 Key + CLI 授权模式。两模式不互相回退。

## 二、角色与权限矩阵

### 2.1 角色来源与认证

- 角色：`admin` / `teacher` / `student`，注册接口接受三种角色；**前端注册页只开放 student/teacher**，admin 需平台负责人创建（当前仅 seed 的 demo admin）。
- 认证：Bearer Token（64 位十六进制，由 OpenSSL `RAND_bytes` 生成），内存 session 数组 128 个、24 小时过期、16 次创建触发清理；密码 SHA-256(固定 salt‖密码)。

### 2.2 权限矩阵（以当前代码为准）

| 操作 | admin | teacher | student |
| --- | --- | --- | --- |
| 注册/登录/登出/me | ✅ | ✅ | ✅ |
| 题目读（列表/详情，含答案） | ✅ | ✅ | ✅ |
| 题目写（新增/改/删） | ✅ | ✅（**无归属隔离**） | ❌ 403 |
| 试卷读 | 全部 | 仅本人创建 | 仅 active（archived 404） |
| 试卷写（CRUD/编排/状态） | 全部 | 仅本人创建 | ❌ 403 |
| 试卷导出/导出策略 | 全部 | 本人（归档卷也可导出） | 仅 active（受策略约束） |
| 教师 AI API 配置 | ❌ 403 | ✅（本人） | ❌ 403 |
| AI 调用（teacher 模式） | ❌（AI_TEACHER_ONLY） | ✅（用自己配置） | ✅（用题目归属教师配置） |
| AI 调用（platform 模式） | 需 CLI 授权 | 需 CLI 授权 | 需 CLI 授权 |
| 用户管理后台 | ❌（无完整后台；admin 可经 API 创建账号） | ❌ | ❌ |

### 2.3 数据归属与隔离规则（现状）

| 数据 | 隔离现状 |
| --- | --- |
| 用户 | username 为唯一键；id 按用户数 +1 生成（demo 简化） |
| 题目 | **无租户隔离**：全库题目对所有登录用户可见；任意 teacher/admin 可改删任意题目；`teacher_id` 仅记录创建者，未用于读/写鉴权 |
| 试卷 | **有归属隔离**：`teacher_id` 从 session 取，teacher 仅本人、admin 全部；student 仅 active |
| 教师 API 凭证 | **有隔离**：`teacher_ai_credentials` 按 teacher_id 主键；AAD 绑定教师 ID/账号键/版本/模型 |
| AI 额度 | **有隔离**：`teacher_ai_usage(student_id, teacher_id, day)` 按"学生+教师+上海自然日"计数 |
| AI 对话/任务 | **有隔离**：Pi 内存 Conversation/Job 绑定 owner(user_id)+question_id，跨用户 404 |

### 2.4 未授权访问处理

- 未登录：题目/试卷/AI/教师 API 接口统一 401 `UNAUTHORIZED`（优先于参数校验）。
- 越权写：题目/试卷 student 写 → 403；teacher 写他人试卷 → 403 `EXAM_FORBIDDEN`；教师 API 非 teacher → 403 `TEACHER_REQUIRED`。
- 越权读：不可见试卷（他人/归档）一律 404 `EXAM_NOT_FOUND`，不泄露存在性；跨用户任务 404 `JOB_NOT_FOUND`。
- 额度耗尽：429 `AI_QUOTA_EXCEEDED`（含 quota 与 Retry-After）。
- 教师未配置/停用：404 `AI_API_NOT_CONFIGURED` / 403 `AI_API_DISABLED`。
- 权限库/加密/存储故障：默认拒绝（fail-closed），503。

## 四、核心业务流程

### 4.1 注册登录

注册（校验用户名非空/密码强度≥8位含字母数字/两次一致/角色合法）→ SHA-256 哈希入库 → 自动建 session 返回 token。登录防枚举（401 不区分）。登出销毁 session。

### 4.2 题目管理

教师/admin 登录 → 列表页"新增/编辑/删除" → 表单提交 → 后端校验（type 二值、options/answer 一致性、知识点字符串数组）→ `kv_set` 写入 `qdata`。seed 5 题（id 1–5）幂等，写题 id=max+1、teacher_id=创建者、status=active。删除题目联动从所有试卷移除引用（`exams_purge_question`）。

### 4.3 试卷管理

创建（name/description）→ 编排（整体替换/追加/移除题目，position 归一化 1..n，score 0<x≤1000）→ 归档/恢复（archived 禁编辑 409）→ 删除（不影响题目本体）。列表/详情按角色过滤，内联题目按 position 升序。

### 4.4 试卷导出

登录 → `GET /exams/{id}/export/{format}?options&answers&analysis&ai` → 后端按可见性+策略（allow_export/allow_answers）渲染文件 → 返回带 Content-Disposition。四种格式手工拼装（PDF 1.4 中文、DOCX 无压缩 OOXML ZIP、Markdown、LaTeX）。单文件上限 8 MiB。AI 解答导出当前恒不支持。

### 4.5 AI 解答（teacher 模式）

1. 学生选题 → `GET /ai/access?question_id=N` 预检查（allowed/reason_code/quota，不扣次）。
2. 学生 `POST /chat` → C 校验登录→模式→题目 active→`teacher_api_resolve`（从题目 `teacher_id` 解析教师配置、校验额度并**预扣 1 次**）。
3. C 解密教师 API Key（AES-256-GCM），组装 execution（api_key/model/teacher_id/version）→ 内部 HTTP 提交 Pi。
4. Pi 入队（并发 4、队列 32、单任务锁）→ Agent 执行（预算 30s/3 模型调用/6 工具/2048 tokens）。
5. 前端 800ms 轮询 `GET /chat/{job_id}` 直到 succeeded/failed/cancelled，展示 reply（含 usage/model）。
6. 同题追问复用 conversation_id；切换模式/题目新建对话。
7. 额度：Pi 明确拒绝（4xx/AI_BUSY）释放预扣；已接受的失败/取消/超时**不退次**。

### 4.6 教师 AI API 配置

教师登录 → `#teacher-api` 页 → `PUT /teacher/ai-api`（api_key+可选 model）→ 后端 AES-256-GCM 加密入库、version 递增、启用；`GET` 只回脱敏 masked_key；`PATCH` 启停。密钥只进后端，前端保存后清空输入框。

## 五、核心数据模型

### 5.1 kv_store 目录式 KV（namespace → 同名 SQLite 表）

| namespace/表 | 存储内容 | value_name |
| --- | --- | --- |
| `users` | 用户 | id / username / name / role / password_hash |
| `qdata` | 题目 | content / options / answer / analysis / type / knowledge_points / seed_key / teacher_id / status |
| `edata` | 试卷 | name / description / teacher_id / status / created_at / updated_at / questions / export_policy |

> 注：`questions` 为 kv 中 value_name；`edata` 由 `exams.c` 直接建表（`CREATE TABLE edata`），`kv_tables` 记录 namespace 元信息。

### 5.2 关系表

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `questions`（遗留骨架） | `db_init` 创建、业务未使用 | id/teacher_id/content/answer/analysis/tags/status/created_at |
| `ai_access_grants` | platform 模式全局 AI 授权 | user_id / enabled / expires_at |
| `ai_access_audit` | platform 模式授权审计 | 操作/操作人/原因/时间 |
| `teacher_ai_credentials` | 教师 API 凭证（加密） | teacher_id PK / owner_key / model / secret / masked_key / enabled / version / updated_at |
| `teacher_ai_usage` | 学生日额度计数 | student_id / teacher_id / day / used |
| `teacher_ai_charges` | 预扣/扣减流水 | student_id / teacher_id / day / created_at |
| `teacher_ai_audit` | 教师 API 操作审计 | teacher_id / version / action / created_at |

外键均为逻辑外键（无 FOREIGN KEY 声明），由应用层校验 identity/owner。

## 六、主要 API 分类

| 分类 | 路径 | 说明 |
| --- | --- | --- |
| 健康 | `GET /api/v1/health` | 无鉴权 |
| 认证 | `POST /api/v1/auth/{register,login,logout}`、`GET /auth/me` | 注册/登录/登出/当前用户 |
| 题目 | `GET/POST/PUT/DELETE /api/v1/questions[/{id}]` | 读全角色，写 teacher/admin |
| 试卷 | `GET/POST/PUT/PATCH/DELETE /api/v1/exams[/{id}]`、`/exams/{id}/questions[/{qid}]` | 归属隔离 |
| 导出 | `GET /api/v1/exams/{id}/export/{format}`、`GET/PUT /exams/{id}/export-policy` | PDF/MD/LaTeX/DOCX |
| AI 权限 | `GET /api/v1/ai/access[?question_id=N]` | teacher 模式需 question_id |
| AI 对话 | `POST /api/v1/chat`、`GET/DELETE /api/v1/chat/{job_id}` | 202 异步 + 轮询/取消 |
| 教师 API | `GET/PUT/PATCH /api/v1/teacher/ai-api` | 仅 teacher |
| 内部（Pi） | `POST/GET/DELETE /internal/v1/jobs[/{id}]`、`GET /health` | AI_SERVICE_TOKEN 鉴权，不对外 |

错误统一格式 `{"error":"...","code":"..."}`（旧题目接口为 `{"error":"..."}`）；写接口带 `Cache-Control: no-store`；405 带正确 `Allow` 头。

## 八、尚存问题与待确认事项

### 8.1 安全与隔离

- 题目写操作无所有权校验（任意 teacher/admin 可改删他人题目），多租户隔离未完整落地。
- 题目写操作为多次 `kv_set`，非单事务，存在半写风险。
- 会话、AI 任务、对话均为内存态，重启即失；审计表只写不读。
- 密码使用固定 salt（demo 取舍）；session token 已用 OpenSSL `RAND_bytes`。

### 8.2 功能完整度

- 试卷导出/导出策略：后端实现、前端未接入。
- 试卷追加/移除单题：后端实现、前端仅用整体替换。
- 未实现：平台配置、批量导入、搜索/筛选/难度/标签、讨论树、个人中心、API 捐赠、重复检测、内容审核、多模型路由、Token/金额计费、审计查询、备份/监控。
- 部分实现：学生提交审核（后端实现、前端审核页未接入）、用户管理后台（仅管理员创建账号）、AI 解答参数（仅 model）、多层级额度（仅学生日额度）。

### 8.3 待确认事项

1. 是否需要为题目增加 `teacher_id` 归属校验以闭合多租户隔离（当前缺口）。
2. 管理员在默认 teacher 模式下的 AI 使用资格（SRS UC-05 与实现冲突）。
3. 导出前端入口是否纳入下一阶段（后端已就绪）。
4. 题目写操作是否需事务化（8 次 kv_set）。
