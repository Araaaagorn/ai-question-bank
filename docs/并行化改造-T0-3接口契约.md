# 并行化改造 · T0-3 技术决策与接口契约

> 状态：**T0-3 交付物（决策定稿 + 接口契约冻结）**，是下游任务 T1-A~T1-E 的唯一实现依据。
> 原则：**先定接口、后写实现**。本契约冻结的是「接口签名 + 语义 + 约束」，各任务可自行选择实现细节，但不得偏离契约；任何接口变更须回到本契约评审后统一改。

---

## 1. 目的与范围

T0-3 的目标是消除下游并行开发的返工：在 T1-A（SQLite 基础设施）、T1-B（Session 加锁）、T1-D（ID 原子化）、T1-E（事务收口）、T1-F（线程池启用）分别动工之前，先把以下事项「定死」：

1. DB 并发方案（连接池 vs 全局锁）；
2. MHD 线程模型（thread-per-connection vs 线程池）；
3. Session 接口语义（消除返回内部指针）；
4. ID 分配的原子接口；
5. 新增配置项及其默认值、校验规则。

---

## 2. 关键决策记录（ADR）

### 2.1 D1：DB 并发方案 → 「连接池 + WAL」，否决全局锁作为主路径

**背景**：现状全局只有一个 `cfg.db`（`main.c:23`），且 `teacher_api.c` 用 `BEGIN IMMEDIATE…COMMIT` 连接级事务。多线程下共享单连接会使事务互相串扰；`sqlite3_config(SERIALIZED)` 只保护单条语句，不能保护跨语句事务。

**决策**：采用**连接池（connection pool）+ WAL**。每个请求线程通过 `db_acquire()` 取得**独占连接**，事务天然绑定线程；读操作走独立读连接；开启 `PRAGMA journal_mode=WAL` 与 `PRAGMA busy_timeout`。

**理由**：
- 连接池让现有 `teacher_api.c` 的 `BEGIN IMMEDIATE` 事务**几乎无需改动**（事务在独占连接上天然隔离）；
- 全局锁方案需要给每一处事务手工配对 lock/unlock，侵入面更大、更易漏锁；
- WAL 下读不阻塞写、写只有一个，适合「多用户同时在线」的读多写少场景。

**否决项**：「单连接 + 全局互斥锁」作为主路径被否决（仅保留为 `db_pool.c` 的内部实现兜底，不暴露给业务层）。

### 2.2 D2：MHD 线程模型 → 「固定 worker 线程池」为主

**决策**：主路径使用 `MHD_USE_INTERNAL_POLLING_THREAD + MHD_OPTION_THREAD_POOL_SIZE(N)`（固定 N 个 worker），N 由环境变量 `MHD_THREADS` 决定；保留 `MHD_USE_THREAD_PER_CONNECTION` 作为调试回退（`MHD_MODE` 切换）。

**理由**：固定线程数提供有界并发，避免「多用户在线」时 per-connection 无限开线程的资源风险；且现有 per-connection 的 `con_cls` + `MHD_OPTION_NOTIFY_COMPLETED` 清理机制在两种模式下都成立，迁移成本低。

### 2.3 D3：Session 接口 → 「拷贝语义」，废弃返回内部指针

**背景**：`session_create` 返回指向 `g_sessions[i].token` 的指针（`auth.c:101`）、`session_validate` 返回 `Session*`（`auth.c:104`），并发 `session_cleanup` 压缩数组会使二者悬垂。

**决策**：Session 接口改为**值拷贝语义**——`session_create` 写入调用方缓冲区；`session_lookup` 把 `user_id/role/name` 拷贝进调用方的 `SessionInfo` 结构。内部用 `pthread_rwlock` 保护数组。

### 2.4 D4：ID 分配 → `counters` 表原子分配

**背景**：`next_question_id`（`routes.c:593`）、`db_create_user`（`db.c:277`）用「`kv_list_keys` 取最大/计数 + 1」，并发必撞 ID；`next_exam_id`（`exams.c:101`）当前仅被 `exams_create` 的 `BEGIN IMMEDIATE` 事务内调用，撞 ID 风险较低，但为统一与稳健仍建议改为 `counters` 自增。

**决策**：新增统一 `id_next(db, ns, &id)` 接口，基于 `counters(name TEXT PRIMARY KEY, value INTEGER)` 表原子自增；要求**唯一且单调递增**，两并发调用者绝不可得到相同 ID。实现用短事务（或 SQLite ≥3.35 的 `UPDATE … RETURNING`），具体 SQL 由 T1-D 决定，但必须通过 T0-2 的并发撞 ID 测试。

### 2.5 D5：新增并发配置项

新增以下环境变量（校验沿用 `config.c` 现有的 `env_or` / 整数范围校验 + 非法回退默认值 + 只记日志不记原始值的模式）：

| 环境变量 | 类型/范围 | 默认 | 生效条件 |
|----------|-----------|------|----------|
| `MHD_MODE` | `thread_pool` / `thread_per_connection` | `thread_pool` | 线程模型 |
| `MHD_THREADS` | int 1..256 | `8` | 仅 `thread_pool` |
| `MHD_CONNECTION_LIMIT` | int 1..65535 | `256` | 连接并发上限（背压） |
| `DB_POOL_SIZE` | int 1..256 | `8` | 连接池大小（须 ≥ `MHD_THREADS`） |
| `SQLITE_BUSY_TIMEOUT_MS` | long 1..60000 | `5000` | WAL 写锁等待 |

> 其中 `MHD_THREADS`、`DB_POOL_SIZE`、`MHD_CONNECTION_LIMIT` 与 `MAX_SESSIONS` 不手改，均由单一底层参数 `AIQB_CONCURRENCY` 计算派生（见 §3.6）；上表默认值即 `AIQB_CONCURRENCY=8` 时的取值。

## 3. 接口契约（C 声明）

### 3.1 `db_pool.h`（新增，T1-A 实现）

```c
#ifndef AIQB_DB_POOL_H
#define AIQB_DB_POOL_H
#include <sqlite3.h>

/* 初始化连接池：打开 path 的 pool_size 个连接，启用 WAL 与 busy_timeout。
 * 必须在派生任何请求线程之前调用（main.c 启动期）。
 * 返回 0 成功 / -1 失败。 */
int db_pool_init(const char *path, int pool_size, long busy_timeout_ms);

/* 获取当前调用线程独占的连接；失败返回 NULL。
 * 连接生命周期由路由边界统一管理（见 §4 约定 1）。 */
sqlite3 *db_acquire(void);

/* 归还连接；归还后调用方不得再使用该句柄。 */
void db_release(sqlite3 *db);

/* 关闭连接池（进程退出时，main.c 收尾）。 */
void db_pool_close(void);
#endif
```

**语义要求**：
- `db_acquire()` 返回的连接对当前线程独占；同一线程在「一个请求」内多次调用应返回同一连接（实现可用线程本地缓存或借用计数，具体由 T1-A 决定）。
- 连接池必须保证 `DB_POOL_SIZE` 个连接可并发被不同线程持有；连接数不够时 `db_acquire` 阻塞等待（受 `SQLITE_BUSY_TIMEOUT_MS` 量级约束）或返回 NULL（业务层按 503 处理）。

### 3.2 `auth.h`（改造，T1-B 实现）

```c
#define SESSION_TOKEN_LEN 64
/* 由 AIQB_MAX_SESSIONS 派生（见 §3.6）；默认 AIQB_CONCURRENCY=8 → 4096。
 * 也可动态扩容，但必须满足「≥ 目标在线用户数」的约束。 */
#define MAX_SESSIONS AIQB_MAX_SESSIONS

typedef struct {
    int  user_id;
    char role[16];
    char name[64];
} SessionInfo;

/* 创建会话，token 写入调用方缓冲区（容量至少 SESSION_TOKEN_LEN+1）。
 * 返回 0 成功 / -1 失败（槽位耗尽或随机源失败）。 */
int session_create(int user_id, const char *role, const char *name,
                   char *token_out, size_t token_out_cap);

/* 校验 token，成功把身份拷贝进 *out 并返回 0；无效/过期返回 -1。
 * out 仅当返回 0 时有效。
 * 保留旧 session_validate 的「过期惰性失效」副作用：命中已过期会话时，
 * 在写锁下置 active=false 后再返回 -1（与方案 §2.2 一致）。 */
int session_lookup(const char *token, SessionInfo *out);

/* 销毁指定 token 的会话。 */
void session_destroy(const char *token);

/* 从 "Authorization: Bearer <token>" 提取 token（不变，直接返回 header 内偏移）。 */
const char *extract_bearer_token(const char *auth_header);
```

**废弃项**：旧的 `const char *session_create(...)` 与 `Session *session_validate(...)` 签名删除；`routes.c` 调用点由 T1-B 同步迁移（`s->role` → `s.role` 等值访问）。

### 3.3 `ids.h`（新增，T1-D 实现；或并入 `db.h`）

```c
#ifndef AIQB_IDS_H
#define AIQB_IDS_H
#include <sqlite3.h>

/* 原子分配 namespace 的下一个正整数 ID，写入 *out_id。
 * 保证：全局唯一、单调递增；并发调用绝不返回相同值。
 * 返回 0 成功 / -1 失败。 */
int id_next(sqlite3 *db, const char *namespace, int *out_id);
#endif
```

**调用方改造**（T1-D）：
- `routes.c:593 next_question_id(db)` → `id_next(db, "qdata", &id)`
- `exams.c:101 next_exam_id(db)` → `id_next(db, "edata", &id)`（该函数当前在 `exams_create` 事务内，改造时保持事务语义）
- `db.c:277 db_create_user` → 用 `id_next(db, "users", &id)` 生成 id

### 3.5 `routes.h` / `http_server.c`（分发边界改造，T1-A 实施）

`route_dispatch` 签名从「内部读 `cfg->db`」改为「显式传入每请求连接」：

```c
enum MHD_Result route_dispatch(struct MHD_Connection *conn, const char *url,
                               const char *method, const char *body,
                               size_t body_len, const AppConfig *cfg,
                               sqlite3 *db /* 每请求独占连接，替换 cfg->db */);
```

`RequestCtx` 增加 `sqlite3 *db;` 字段；在 `request_handler` 分发前 `ctx->db = db_acquire();`，在 `request_completed` 中 `db_release(ctx->db);`（连接中断路径也会释放）。

### 3.6 宏依赖派生方案（单一底层参数，改一处联动全部）

为避免「有依赖关系的宏」各自硬编码、改一处漏一处，约定：**派生宏一律用计算表达式引用单一底层参数 `AIQB_CONCURRENCY`**。

```c
/* —— 唯一底层参数：目标并发 worker 数。调整并发规模时只改这一处 —— */
#define AIQB_CONCURRENCY 8

/* —— 派生宏（由 AIQB_CONCURRENCY 计算而来，勿手改）—— */
#define AIQB_MHD_THREADS            (AIQB_CONCURRENCY)          /* worker 线程数 */
#define AIQB_DB_POOL_SIZE           (AIQB_MHD_THREADS)          /* 每 worker 一个独占连接 */
#define AIQB_MHD_CONNECTION_LIMIT   (AIQB_MHD_THREADS * 32)     /* 每 worker 排队连接上限 */
#define AIQB_MAX_SESSIONS           (AIQB_MHD_THREADS * 512)    /* 会话槽位（含过期/多端余量） */
```

取值：`AIQB_CONCURRENCY=8` → `MHD_THREADS=8`、`DB_POOL_SIZE=8`、`MHD_CONNECTION_LIMIT=256`、`MAX_SESSIONS=4096`。

**既有超时宏的依赖**（`config.h`）同样用计算表达，底层参数为内部 HTTP 总超时：

```c
#define AI_REQUEST_TIMEOUT_MS_DEFAULT 2000L   /* 底层参数：内部 HTTP 总超时 */
#define AI_CONNECT_TIMEOUT_MS_DEFAULT (AI_REQUEST_TIMEOUT_MS_DEFAULT / 4)  /* 连接超时 */
#define AI_SERVICE_TIMEOUT_MS_MAX     (AI_REQUEST_TIMEOUT_MS_DEFAULT * 30) /* 校验上限 */
```

（当前取值 2000 → 500 / 60000，与现状一致。）

## 4. 必须遵守的约定与约束

1. **连接生命周期**：`db_acquire/db_release` 只在「路由边界」配对（分发前 acquire、完成回调 release）；业务函数（`kv_*`、`exams_*`、`teacher_api_*`、`db_*`）**一律通过参数接收 `db`，禁止在函数内部自行 acquire/release**。
2. **事务约定**：任何 `BEGIN IMMEDIATE…COMMIT/ROLLBACK` 必须全程使用同一个传入的 `db`（线程独占，天然隔离），事务期间不得调用其它会换连接的逻辑。
3. **派生顺序**：`sqlite3_config(SQLITE_CONFIG_SERIALIZED)`（如需）在 `db_pool_init` 之前；所有 `*_init`/seed 在派生 MHD worker 线程之前完成。
4. **只读共享状态约定**：`AppConfig cfg`、`g_base_dir` 在派生线程后视为只读，不设锁（固化注释）。
5. **静态缓冲**：`kv_store.c safe_table_name` 必须消除 `static char buf[256]` 共享（`_Thread_local` 或调用方缓冲），由 T1-C 完成。

## 6. 决策验收标准

- **D1/D2**：`make build && make test` 全绿；`T0-1` 压测下 P99 与并发数解耦；无 `SQLITE_BUSY` 崩溃。
- **D3**：`T0-2` 并发登录/登出 + 会话清理下无越界、无脏读、token 不悬垂。
- **D4**：`T0-2` 并发注册/建题/建卷下 ID 全局唯一。
- **D5**：非法配置值回退默认并只记日志；合法值生效。
