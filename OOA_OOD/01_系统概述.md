## 1. 项目背景

随着大模型能力进入教学场景，传统题库系统难以满足个性化答疑与知识沉淀的需求。本项目（AI+题库智能教学平台）是一个面向教育场景的**多教师、多学生、多租户**智能题库与试卷管理平台：教师维护题库/试卷并配置 AI 解答能力，学生提交题目、查看 AI 解答并在对话中追问，管理员负责用户、全局配置、审计与运维（来源：`README.md`、`docs/AI题库项目整体预期功能说明书.md` §1-2）。

项目同时是软件工程课程实践项目：monorepo、受保护 main 分支、PR + CI + 至少 1 人 Review 的协作流程（`CONTRIBUTING.md`、`docs/architecture.md` §协作规范）。

## 2. 系统目标

1. 题目资源数字化管理：题目作为独立实体，可归属教师、可复用、带知识点标签（当前实现子集）。
2. AI 辅助教学与答疑：后端统一代理大模型，提供完整讲解（solve）、分层提示（hint）、错因分析（review）三种教学模式与异步任务机制。
3. 师生知识协同沉淀：同题多轮追问对话（分支讨论树为目标功能）。
4. 可控的 AI 使用：教师自管 API Key（加密存储）+ 学生日额度（默认 20 次/学生/教师/上海自然日）。
5. 安全边界：API Key 不出后端、会话与角色校验、静态文件路径穿越防护、敏感信息脱敏与擦除。

## 3. 用户角色

| 角色 | 标识 | 职责（已实现部分） | 依据 |
| --- | --- | --- | --- |
| 管理员 | `admin` | 登录/登出/查询自身信息；与教师同权的题目写接口；演示题归属者（seed 题 teacher_id=1） | `server/src/routes.c`、`docs/auth.md` §4 |
| 教师 | `teacher` | 题目增删改；配置/启停自己的 AI API；查看脱敏配置 | `routes.c` 写权限检查、`teacher_api_routes.c` |
| 学生 | `student` | 浏览题目与详情；提交 AI 解答任务、追问、查询/取消任务；受日额度约束 | `routes.c handle_chat`、`teacher_api.c` |
| 运维人员 | —（非 HTTP 参与者） | 仅 platform 兼容模式下经服务器 CLI 授予/撤销平台 AI 授权（grant/revoke，同事务写审计） | `scripts/ai_access.py`、`docs/ai-access.md` |
| AI 模型供应商 | 外部系统 | DeepSeek 兼容 Chat Completions 接口；由 Pi 服务调用 | `ai-service/src/agent.ts`、`config.ts` |

**说明**：AI 服务（Pi）、数据库、任务队列均为系统内部组件，不作为用户参与者；运维人员是服务器侧操作角色，仅在 platform 兼容模式存在，默认 teacher 模式不使用（`docs/ai-access.md`、`docs/teacher-api.md`）。

## 4. 系统边界

- **边界内**：`web/` 静态前端、`server/` C11 后端（唯一公共业务入口）、`ai-service/` 内部 Pi AI 服务（仅监听 127.0.0.1）、SQLite 数据库文件、`scripts/` 运维脚本（服务器侧）。
- **边界外**：浏览器用户、AI 模型供应商、课程服务器操作系统/systemd（`deploy/systemd/ai-question-bank.service`）。
- **接口约定**：公共 API 前缀 `/api/v1/*`，JSON + Bearer Token；C→Pi 内部接口 `/internal/v1/jobs*`，独立服务凭证 `AI_SERVICE_TOKEN` + `X-User-Id` 头（`docs/architecture.md` §7、`ai-service/src/server.ts`）。

## 5. 技术架构

```
浏览器(SPA, hash路由)
   │  HTTP/JSON /api/v1/*（Bearer 用户 token）
   ▼
server（C11）libmicrohttpd 单轮询线程
   ├─ routes.c        路由分发 + 业务处理器
   ├─ auth.c          内存会话（128 槽，24h）
   ├─ teacher_api.c   教师 Key AES-256-GCM 加密 + 日额度事务
   ├─ ai_access.c     平台授权（platform 模式）
   ├─ ai_client.c     libcurl 内部代理（连接500ms/总2000ms）
   ├─ kv_store.c/db.c SQLite 存取（namespace→同名表）
   │        │ 内部 HTTP（AI_SERVICE_TOKEN）
   │        ▼
   │   ai-service（Node≥22.19 / TS / Pi 0.84.1）
   │        ├─ server.ts 内部接口鉴权
   │        ├─ jobs.ts   有界队列（并发4/等待32/TTL 1h）
   │        └─ agent.ts  每任务独立 Agent（30s/3模型/6工具）
   │                 │
   │                 ▼
   │        AI 模型供应商（DeepSeek 兼容）
   └─ 静态托管 web/（路径穿越防护）
```

| 层 | 技术 | 关键约束 |
| --- | --- | --- |
| 前端 | 纯 HTML/CSS/JS，无构建链；hash 路由；file:// 离线演示回退 | `web/index.html`、`web/js/api.js` |
| 后端 | C11、libmicrohttpd、SQLite3、libcurl、cJSON、OpenSSL | 单轮询线程串行假设；请求体 ≤64KiB |
| AI 服务 | Node.js ≥22.19、TypeScript、Pi 0.84.1（pi-ai + pi-agent-core） | 仅 127.0.0.1；状态仅内存 |
| 构建/部署 | GNU Make（根 Makefile 模块化分派）、gcc；systemd | `Makefile`、`deploy/systemd/` |
