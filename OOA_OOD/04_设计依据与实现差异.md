## 4.2 需求—代码—设计三方不一致清单（本次核查发现）

1. **`docs/kvstore.md` 表名前缀过时**：文档称 namespace 映射 `kv_{ns}`，实际 `safe_table_name()` 生成同名表（`users`/`qdata`）；`ai-access.md` 已勘误。本文档与图一律以代码为准。
2. **SRS F-09 状态过期**：SRS v1.2 记"`POST /api/v1/chat` 尚未实现、前端降级演示数据"，当前 chat 全链路已实现（Pi v1.2/v1.3）；前端仍保留 404/405/501 回退逻辑作为历史兼容。
3. **前端与 1.3 契约脱节**：`api.js aiAccess()` 不带 `question_id`；默认 teacher 模式下 `/ai/access` 返回 400，对话页发送按钮被禁用（除非离线演示）。README/teacher-api.md 均声明"web 页面本次未改"，属**已知且被文档承认的集成差距**，但 SRS/Backlog 未单列条目——本文档将其记为 🟡 并给出 💡 修复建议。
4. **questions.md 与列表实现细微差异**：文档称列表"返回全部 active 题目"，代码列表不按 status 过滤（当前数据全为 active，行为等价）；chat 提交才校验 active。状态图 1 已如实注明。
5. **演示题归属**：seed 题 teacher_id=1（admin），README 明示"不会自动转移"，教师联调需自建题目——用况图 2 的归属解析用况对此有注释。
6. **archived 语义空缺**：需求与 SRS 字段表含 archived，代码无写入路径；状态图以"预留状态"表达，未虚构归档接口。

## 4.3 新增设计建议（💡，均非当前实现）

1. **前端 1.3 升级**：`API.aiAccess(questionId)` 携带 question_id；渲染 quota（used/remaining/reset_at）与 reason_code 文案；教师角色显示配置入口。
2. **教师 API 配置页与题库管理页**：接口已完备（PUT/PATCH/GET、题目 CRUD），补页面即可闭合教师工作流。
3. **题目写操作事务化**：`handle_question_create` 的 8 次 kv_set 建议包入单事务（或提供补偿），避免半写题目。
4. **讨论树持久化与 Fork**：按建议表 `conversation_nodes`（parent_id 自关联）落地 SRS F-11；Pi 内存对话增加落盘策略。
5. **通用审计与访问日志**：建议表 `audit_logs` + 统一中间件记录登录/写操作/AI 调用（含 token 用量），支撑 SRS F-15。
6. **备份策略**：SQLite 文件定时备份 + `AI_KEY_ENCRYPTION_KEY` 分离保管与恢复演练脚本。
7. **文档修订**：更新 `docs/kvstore.md` 表名表述；在 SRS 中刷新 F-05/F-09/F-12 状态并新增"前端 1.3 集成"条目。
8. **索引与检索**：为支撑题目搜索/筛选（P1），建议为 qdata 增加 teacher_id/status 映射表或生成列索引。
